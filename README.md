# card-game

덱빌딩 로그라이크 프로토타입. **1단계: 전투 시스템만** 구현된 상태다.

인스크립션 스타일의 웨이브 방어형 턴제 전투. 몬스터 덱에서 뽑힌 적이 예고로
올라오고, 다음 턴에 내려와 플레이어 유닛과 교전한다.

## 실행

```bash
npm install
npm run dev        # 개발 서버 (http://localhost:5173)
npm run typecheck
npm test           # 33개 테스트
npm run build
```

## 전투 규칙

**보드**: 3레인. 각 레인은 세 칸을 가진다.

| 칸 | 내용 |
| --- | --- |
| 예고 | 다음 턴에 내려올 적 |
| 적 | 이미 내려와 이번 턴 종료 시 공격하는 적 |
| 내 유닛 | 배치한 플레이어 유닛 |

**턴 흐름** (`endTurn`):

1. **교전** — 같은 레인의 적과 유닛이 *동시에* 서로를 때린다. 죽는 유닛도 반격은
   들어간다. 막는 유닛이 없으면 적의 공격력만큼 플레이어 HP가 깎인다.
2. **사망 처리** — 모든 레인의 교전이 끝난 뒤 한 번에 처리한다.
3. **강하** — 예고된 적이 아래로 내려온다. 적 칸이 아직 차 있으면 예고로 대기한다.
4. **새 예고** — 몬스터 덱에서 1장을 뽑아 비어 있는 레인에 올린다.
5. **다음 턴** — 에너지를 최대치로 리셋하고 1장 드로우한다.

예고가 교전 *뒤에* 내려오므로, 플레이어는 적이 필드에 서 있는 모습을 한 턴 보고
나서 대비할 수 있다.

**확정된 규칙**

- **배치 코스트**: 에너지. 매 턴 최대치(2)로 리셋되며, 한도 안에서 여러 장 배치 가능.
- **승리**: 몬스터 덱 소진 + 필드 정리(적·예고 모두 없음). **패배**: HP 0.
- **손패**: 누적. 매 턴 1장 드로우하고, 안 낸 카드는 그대로 남는다.
- **유닛**: 소모형이 아니라 죽을 때까지 필드에 남는다.

## 밸런스

자동 플레이 300판 기준 **승률 71%, 중앙 8턴(6~11), 승리 시 잔여 HP 7.7/10**.

튜닝하며 나온 제약 두 가지:

- **전투 길이 ≈ 몬스터 덱 크기.** 예고가 턴당 1장만 올라오므로, 5~8턴 목표를
  지키려면 몬스터 덱은 5~6장이어야 한다. 덱을 더 키우려면 턴당 예고 수를
  늘리는 규칙이 필요하다.
- **몬스터 체력은 낮게.** 체력이 높으면 적이 레인에 눌러앉아 뒤의 예고를 막고
  전투가 10턴 넘게 늘어진다. 공격력 높고 물렁하게 잡아야 레인이 회전한다.
- **에너지 3은 너무 많다.** 예고 1장/턴에 에너지 3이면 플레이어가 턴당 1.5장을
  깔아 항상 앞선다(승률 97%). 2로 낮춰야 "이번 턴엔 뭘 포기할지" 선택이 생긴다.

## 구조

```
src/engine/rng.ts      시드 기반 결정론적 RNG
src/engine/types.ts    카드·레인·전투 상태 타입
src/engine/combat.ts   전투 규칙 (DOM 의존 없음)
src/data/cards.ts      더미 카드/덱 데이터
src/ui/render.ts       DOM 렌더링 (상태를 읽기만 한다)
tests/                 Vitest
```

엔진과 UI는 분리돼 있다. 규칙 판정은 전부 `combat.ts`에 있고 UI는 `canPlayCard`로
배치 가능 여부만 물어본다. 무작위는 전부 인자로 받은 `Rng`를 통해서만 발생하므로
같은 시드는 같은 전투를 재현한다.

## 아직 정하지 않은 것

- **바닥 타일 덱(맵 구성) 도입 여부** — 1단계 범위 밖이라 손대지 않았다.
- **런 구조** — 2지선다 선택지, 전투 간 덱 변화, 런 종료 조건.
- **턴당 예고 수** — 현재 1장 고정. 몬스터 덱을 키우려면 여기부터 손봐야 한다.
